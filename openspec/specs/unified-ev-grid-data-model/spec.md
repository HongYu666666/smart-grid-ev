## Requirements
### Requirement: 公共对象具有稳定身份和来源
所有跨模块交换的定义对象、状态、事件、动作、结果和错误 MUST 具有稳定身份、
运行归属、schema/生产者版本和可追踪来源。公共身份 MUST 独立于候选后端的
行号、DataFrame 索引、内部类实例或临时内存地址。

#### Scenario: 候选后端对象进入公共边界
- **WHEN** 适配器把 pandapower、OpenDSS、V2Sim 或其他后端对象转换为新系统对象
- **THEN** 输出使用新系统稳定 ID、来源和版本，并且上层无需读取候选私有对象即可识别和追踪该对象

#### Scenario: 对象来源缺失
- **WHEN** 输入对象没有来源、版本或无法解析其稳定 ID
- **THEN** 系统拒绝把它作为正式输入，并返回可定位的结构化错误

### Requirement: 时间和单位语义跨模块一致
跨模块数据 MUST 同时表达运行标识、带时区的绝对时间或明确的相对时间、
仿真步索引和时间步长。所有物理数值 MUST 绑定明确单位，单位和时间转换
MUST 在边界显式执行并留下转换记录。

#### Scenario: 多源数据进入同一状态快照
- **WHEN** 配网、车辆、交通和充电设施数据被组合为同一步状态快照
- **THEN** 所有数据属于同一 `run_id` 和可比较时刻，单位已经显式对齐，超出允许偏差的数据被拒绝或标记不可用

#### Scenario: 输入使用隐式本地时间或未知单位
- **WHEN** 模块收到没有时区/相对时标说明的时间或没有单位的物理数值
- **THEN** 模块不得猜测其含义，并返回时间或单位校验错误

### Requirement: 定义对象、时序值、状态快照和事件分离
统一模型 MUST 区分相对稳定的定义对象、带时标的时序值、同一步一致状态快照
和离散事件。状态快照 MUST 只包含已确认事实，不得混入尚未通过校验的智能体
动作提案。

#### Scenario: 构建可发布状态快照
- **WHEN** 场景编排层发布某个 `step_index` 的状态
- **THEN** 快照引用确定版本的定义对象和已提交事实值，并记录组成快照的数据版本与质量状态

#### Scenario: 回放已记录运行
- **WHEN** 系统基于事件和已接受动作回放某次运行
- **THEN** 回放使用已记录事实推进状态，不隐式重新调用非确定性智能体生成新提案

### Requirement: 跨领域对象引用完整
配电网、常规负荷、车辆、交通、充电设施和控制流之间的引用 MUST 可配置、
可检查并可追踪。引用端点、对象类型、有效时间和映射版本 MUST 明确。

#### Scenario: EV 聚合负荷映射到配网
- **WHEN** 充电站或 EV 聚合负荷被提交给配网适配器
- **THEN** 每项负荷引用有效配网对象和映射版本，功率单位与符号约定明确，无法解析的映射使该输入被拒绝

#### Scenario: 引用对象不存在
- **WHEN** 场景输入包含悬空引用、重复公共 ID 或类型不兼容的映射
- **THEN** 系统拒绝启动或拒绝该批输入，并列出冲突对象与来源

### Requirement: 事件可排序、关联和回放
事件 MUST 表达事件身份、类型、发生时间、记录时间、来源、影响对象、负载、
运行归属和因果/关联关系。事件排序和冲突处理规则 MUST 由模块级 spec 明确，
并遵守系统统一时间语义。

#### Scenario: 同一步出现跨领域事件
- **WHEN** 同一仿真步出现车辆到站、充电开始和配网负荷变化事件
- **THEN** 系统能按批准的因果/优先级规则确定处理顺序，并保留三者之间的关联链

#### Scenario: 事件晚到或重复
- **WHEN** 模块收到超出允许时间窗口的事件或重复事件 ID
- **THEN** 系统按明确规则拒绝、去重或标记补偿，且不得静默重复修改状态

### Requirement: 动作具有校验和执行生命周期
动作 MUST 具有提议者、目标对象、有效时间、参数、策略版本、依据的状态快照
和显式生命周期。智能体 SHALL 只产生 `proposed` 动作；孪生/安全校验层 SHALL
决定接受或拒绝；后端 SHALL 只执行已接受动作。

#### Scenario: 动作通过全部校验
- **WHEN** 动作的 Schema、时序、对象、资源、SOC、功率、潮流和业务约束全部通过
- **THEN** 动作进入已接受/执行状态，执行结果与新状态原子提交并可追踪到原提案和校验记录

#### Scenario: 动作被拒绝
- **WHEN** 任一批准的校验失败
- **THEN** 动作进入拒绝状态，返回结构化原因，且事实状态保持不变

#### Scenario: 动作执行中失败
- **WHEN** 已接受动作在后端或跨模块执行期间失败
- **THEN** 系统不得留下半提交状态，并进入已回退或安全保底状态，保存失败阶段和补偿证据

### Requirement: 后端适配器不泄漏私有模型
配网和 EV/交通后端适配器 MUST 把统一输入转换为候选后端输入，并把后端输出
转换为统一结果或错误。公共调用者 MUST NOT 依赖 pandapower DataFrame、
V2Sim 内部类或其他候选私有结构。

#### Scenario: 替换配网 PoC 后端
- **WHEN** 同一统一配网输入分别交给两个满足适配合同的候选后端
- **THEN** 上层使用相同公共结果/错误语义比较输出，无需改变场景、动作或指标模块

#### Scenario: 保留后端诊断信息
- **WHEN** 后端返回公共合同未覆盖的诊断数据
- **THEN** 适配器可将其作为带来源的诊断附件保存，但不得要求上层据此判断基本执行结果

### Requirement: 结果和错误结构化
所有执行结果 MUST 关联运行、输入、动作/事件、时间、生产者和版本。错误 MUST
至少区分输入/引用/时间/单位校验、后端不可用、求解不收敛、动作违规、超时、
执行失败和内部异常，并表达可重试性与安全状态。

#### Scenario: 配网求解不收敛
- **WHEN** 配网后端无法对已接受输入得到收敛结果
- **THEN** 适配器返回统一的不收敛错误、运行元数据和诊断引用，不伪造电压/载流结果，也不只返回日志字符串

#### Scenario: 输入错误与内部错误区分
- **WHEN** 相同调用分别因非法输入和适配器内部异常失败
- **THEN** 调用者可以通过公共错误类型决定修正输入、重试、回退或停止运行

### Requirement: 指标定义和值可追踪
指标定义 MUST 与指标值分开版本化，并包含含义、单位、窗口、聚合方法、缺失值
处理和基准方案。指标值 MUST 回链到运行、输入、状态、事件和结果证据。

#### Scenario: 计算业务需求覆盖率
- **WHEN** 系统汇总某场景通过测试的需求数与需求总数
- **THEN** 覆盖率结果引用需求版本、测试结果和运行证据，并能按任务书口径继续汇总架构平均覆盖率

#### Scenario: 指标输入不完整
- **WHEN** 计算指标所需结果缺失或质量状态不满足要求
- **THEN** 指标被标记为不可计算或受限，不以默认零或参考项目结果替代

### Requirement: 运行证据可复现
每次可验收运行 MUST 记录 schema、数据集、配置、后端/模型/策略版本、输入哈希、
动作序列、事件、随机种子、环境、开始/结束时间、退出状态和结果引用。

#### Scenario: 同版本回放
- **WHEN** Reviewer 使用同一版本化输入、配置、动作和随机种子回放运行
- **THEN** 系统生成可比较结果和差异报告，差异超过批准阈值时不得判为可复现

#### Scenario: 只存在参考项目证据
- **WHEN** v1、V2Sim 或候选后端运行成功但新系统没有自身运行记录
- **THEN** 参考证据被单独登记，新系统需求状态不得升级为已验证或部分具备

### Requirement: 成员模块级 Spec 追踪上层契约
成员创建的模块级 OpenSpec change MUST 声明上层 change、对应 Requirement/
Scenario、负责模块、必须遵守的外部契约、允许自行决定的内部设计、依赖和验收。

#### Scenario: 成员细化数据准备模块
- **WHEN** member 为场景数据准备模块定义字段、校验、转换、错误和测试
- **THEN** 该 change 映射到本 spec 的身份、时间、单位、引用和版本要求，同时可以自行决定内部类、存储和处理流程

#### Scenario: 细化方案需要改变公共契约
- **WHEN** member 发现模块实现需要改变公共对象语义、动作生命周期或适配边界
- **THEN** 实现暂停并提出上层 spec 修订，经 lead 和 Reviewer 批准后再继续，不在模块 PR 中静默改变系统契约
