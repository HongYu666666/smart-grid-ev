## ADDED Requirements

### Requirement: 场景输入包具有完整清单和运行上下文
数据准备/场景输入模块 MUST 以带清单的场景输入包为唯一外部输入单位。输入包 MUST
声明包标识与版本、目标场景标识与版本、公共 schema 版本、带时区的起止时间、时间
步长与步索引起点、数据集条目清单、跨域映射条目、随机种子或其引用，以及本次运行
的必备条目集合。模块 MUST NOT 从清单之外的路径隐式补齐输入。

来源追踪：`REQ-EV-001`、`REQ-EV-009`；上层 Requirement「公共对象具有稳定身份和
来源」「运行证据可复现」。

#### Scenario: 提交完整输入包
- **WHEN** 输入包声明了包身份、场景、schema 版本、时间上下文、数据集清单、跨域映射、随机种子引用和必备条目集合，且各条目均可解析
- **THEN** 模块产出判定结论为可用的输入视图，并记录本次输入的包版本、schema 版本和条目版本

#### Scenario: 清单与实际条目不一致
- **WHEN** 清单声明的必备条目在输入包中不存在，或存在未在清单中登记的条目被引用
- **THEN** 模块返回清单不完整错误、列出缺失或未登记的条目标识，并拒绝启动，不加载任何部分状态

#### Scenario: schema 主版本不受支持
- **WHEN** 输入包声明的公共 schema 主版本不在模块支持范围内
- **THEN** 模块返回 schema 不兼容错误并拒绝启动，MUST NOT 按旧版本猜测字段含义或静默降级解析

### Requirement: 数据集条目声明来源、位置、完整性和共享边界
每个数据集条目 MUST 声明稳定数据集标识与版本、语义类别、来源类型、位置类别、
完整性证据或明确的无完整性证据声明、质量状态和共享边界。位置类别 MUST 至少区分
仓库内、仓库外受限和生成自固定参数。条目 MUST NOT 使用个人绝对路径作为位置声明。

来源追踪：`REQ-EV-001`、`REQ-EV-009`；上层 Requirement「公共对象具有稳定身份和
来源」。

#### Scenario: 条目缺少来源或版本
- **WHEN** 某数据集条目没有来源类型、版本或位置类别
- **THEN** 模块返回来源不可确定错误并拒绝把该条目作为正式输入

#### Scenario: 参考项目资产作为输入来源
- **WHEN** 某条目只能从 `ev_charging_v1`、V2Sim 或 pandapower 等参考项目取得
- **THEN** 该条目的来源类型登记为参考项目资产、质量登记为参考或受限，并在缺口中记录正式数据待取得，MUST NOT 被表述为项目正式数据

#### Scenario: 条目声明个人绝对路径
- **WHEN** 条目位置声明包含本机用户目录或个人绝对路径
- **THEN** 模块返回来源不可确定错误，要求改为数据集标识与位置类别

### Requirement: 启动前校验按固定顺序执行并给出可定位结论
模块 MUST 按包级、来源级、身份级、度量级、引用级、质量级的固定顺序执行启动前
校验，前一层存在阻塞性问题时 MUST NOT 进入后一层。校验结论 MUST 为可用、受限
可用或拒绝三者之一，并且每条问题 MUST 可定位到数据集条目、对象或字段。

来源追踪：`REQ-EV-001`、`REQ-EV-008`；上层 Requirement「时间和单位语义跨模块
一致」「跨领域对象引用完整」。

#### Scenario: 来源层失败时不产生次生错误
- **WHEN** 某必备条目在来源级校验即失败
- **THEN** 模块返回该来源级错误并停止后续层校验，不再报告由该条目派生的身份、度量或引用错误

#### Scenario: 校验结论可复核
- **WHEN** Reviewer 对同一输入包重复执行校验
- **THEN** 得到相同的判定结论和相同的问题集合，且每条问题给出条目/对象/字段位置、期望与实际

### Requirement: 公共对象身份唯一且独立于参考后端
输入视图中的每个定义对象 MUST 具有稳定、唯一、带类型或命名空间的公共 ID。模块
MUST 拒绝重复、缺失或类型不符的公共 ID。公共 ID MUST NOT 直接采用 pandapower
DataFrame 索引、文件行号、V2Sim 内部对象或临时内存标识。

来源追踪：`REQ-EV-001`、`REQ-EV-008`、`REQ-EV-012`；上层 Requirement「公共对象
具有稳定身份和来源」「后端适配器不泄漏私有模型」。

#### Scenario: 参考数据行号被用作公共 ID
- **WHEN** 输入条目仅以后端行号或 DataFrame 索引标识配网母线、线路或负荷
- **THEN** 模块返回身份冲突错误，要求提供独立的公共 ID 及其与来源标识的映射

#### Scenario: 同一命名空间出现重复 ID
- **WHEN** 两个不同对象在同一命名空间使用相同公共 ID
- **THEN** 模块返回身份冲突错误、列出冲突对象及其来源条目，并拒绝启动

### Requirement: 单位、符号和时间在入口显式统一并留痕
所有物理与业务量 MUST 绑定明确单位和符号约定；所有时间 MUST 表达带时区的绝对
时间或明确的相对时间与步索引。单位换算、时区归一、时间重采样和标幺值基准换算
MUST 只在本模块入口执行，并 MUST 记录原始值、原始单位或原始时标、目标形式、
转换规则标识。模块 MUST NOT 猜测缺失的单位、时区或符号含义。

来源追踪：`REQ-EV-001`、`REQ-EV-002`、`REQ-EV-005`；上层 Requirement「时间和
单位语义跨模块一致」。

#### Scenario: 负荷数据需要单位与粒度对齐
- **WHEN** 常规负荷以 15 分钟粒度提供且单位与配网输入不同
- **THEN** 模块在入口完成单位换算与重采样，输出统一后的时序值，并保存原始单位、原始粒度和转换规则标识

#### Scenario: 数值缺少单位或时间缺少时区
- **WHEN** 某功率字段没有单位声明，或某时间戳既无时区也无相对时标说明
- **THEN** 模块返回度量非法错误并拒绝该条目，MUST NOT 采用默认单位或本地时区

#### Scenario: 数值超出允许域
- **WHEN** 输入包含 SOC 超出 `[0,1]`、负容量或负时长等越域数值
- **THEN** 模块返回度量非法错误，定位到对象与字段，并拒绝把该值写入输入视图

### Requirement: 跨域引用在启动前完整可解析
车辆与道路、车辆或充电会话与站点/桩、站点或 EV 聚合负荷与配网对象、常规负荷与
配网对象之间的引用 MUST 在启动前全部可解析，并 MUST 声明端点类型、有效时间和
映射版本。存在悬空引用、端点类型不兼容或缺映射版本时，模块 MUST 拒绝启动并列出
冲突对象与来源条目。

来源追踪：`REQ-EV-008`、`REQ-EV-003`、`REQ-EV-004`、`REQ-EV-005`；上层
Requirement「跨领域对象引用完整」。

#### Scenario: 站点映射到不存在的配网节点
- **WHEN** 某充电站或 EV 聚合负荷引用的配网节点在定义对象集合中不存在
- **THEN** 模块返回引用不可解析错误、列出该站点与目标节点标识，并拒绝启动

#### Scenario: 映射缺少版本
- **WHEN** 跨域映射条目没有声明映射版本或有效时间
- **THEN** 模块返回引用不可解析错误，要求补齐映射版本与有效时间

#### Scenario: 引用全部可解析
- **WHEN** 所有车辆、道路、站点、桩、聚合负荷和配网对象引用均可解析且类型兼容
- **THEN** 输入视图包含已校验的跨域映射集合及其映射版本，供下游模块直接使用

### Requirement: 缺口区分阻塞启动与受限可用
模块 MUST 按输入包声明的必备条目集合判定缺口后果。必备条目缺失、不可解析或质量
为不可用时 MUST 拒绝启动。非必备条目缺失或质量为估算/受限时 SHALL 允许判定为
受限可用，但输入视图和输入侧证据 MUST 标记受限条目、受限原因和受影响的需求或
指标。模块 MUST NOT 用默认值、零值或参考项目样例静默填补缺口。

来源追踪：`REQ-EV-001`、`REQ-EV-010`、`REQ-EV-011`；上层 Requirement「指标定义
和值可追踪」「只存在参考项目证据」。

#### Scenario: 必备条目不可用
- **WHEN** 被声明为必备的配网拓扑或车辆行程条目缺失或质量为不可用
- **THEN** 模块返回质量不可用错误并拒绝启动，不进入任何孪生初始化

#### Scenario: 非必备条目受限
- **WHEN** 电价或交通流条目只有参考项目来源且质量为受限，且未被声明为必备
- **THEN** 模块判定为受限可用，输入视图标记该条目受限，并列出受影响的需求与指标

#### Scenario: 受限输入被用于结论
- **WHEN** 下游基于受限可用输入生成结果
- **THEN** 输入侧证据中的受限标记保持可见，该结果 MUST NOT 被表述为可复现结论或指标达标证据

### Requirement: 输入错误结构化且可区分处置方式
模块返回的输入错误 MUST 至少区分 schema 不兼容、清单不完整、来源不可确定、
完整性缺失、身份冲突、度量非法、引用不可解析、质量不可用和模块内部错误。每条
错误 MUST 表达类别、可定位对象或条目、期望与实际、是否可重试，以及当前是否允许
启动。模块 MUST NOT 仅返回日志字符串或布尔失败标记。

来源追踪：`REQ-EV-001`、`REQ-EV-007`；上层 Requirement「结果和错误结构化」。

#### Scenario: 输入错误与内部错误区分
- **WHEN** 同一输入包分别因非法单位和模块自身异常失败
- **THEN** 调用方可通过错误类别区分“修正输入后重试”与“上报模块缺陷”，且内部错误不被表述为输入问题

#### Scenario: 一次校验返回多条同层问题
- **WHEN** 同一校验层存在多条互不派生的问题
- **THEN** 模块一次性返回该层全部问题，每条均可独立定位，避免逐条试错

### Requirement: 仓库外受限数据只登记元数据
对于不能进入 Git 的受限数据，模块 MUST 仅依赖数据集标识、版本、完整性证据、位置
类别和共享边界进行校验。仓库 MUST NOT 包含受限数据文件、密钥或个人绝对路径。
缺少完整性证据的受限条目 MUST 在输入视图和证据中标记为不可独立校验。

来源追踪：`REQ-EV-001`、`REQ-EV-009`；上层 Requirement「公共对象具有稳定身份和
来源」「运行证据可复现」。

#### Scenario: 受限区域数据包作为输入
- **WHEN** 输入引用仅在项目组内共享、已登记 SHA-256 的区域数据包
- **THEN** 模块使用标识、版本和哈希完成来源与完整性校验，仓库中不出现该数据文件或其本机路径

#### Scenario: 受限条目缺少哈希
- **WHEN** 某受限条目无法提供哈希或其他完整性证据
- **THEN** 该条目被标记为不可独立校验；若其被声明为必备，模块返回完整性缺失错误并拒绝启动

### Requirement: 输入侧证据支持同版本回放
模块 MUST 为每次判定产出输入侧证据记录，至少包含包标识与版本、schema 版本、
数据集条目及其版本/完整性证据/质量状态、转换记录摘要、跨域映射版本、随机种子
引用、判定结论和生成时间。缺少版本或完整性证据的条目 MUST 标记为不可独立校验。

来源追踪：`REQ-EV-009`、`REQ-EV-011`；上层 Requirement「运行证据可复现」。

#### Scenario: 同输入包重复加载
- **WHEN** 使用同一输入包、同一 schema 版本和同一随机种子引用重复执行输入准备
- **THEN** 产出相同的输入视图内容和相同的输入侧证据记录（除生成时间外），支持下游回放与差异比较

#### Scenario: 输入未完全固定
- **WHEN** 输入侧证据中存在被标记为不可独立校验的条目
- **THEN** 基于该输入的运行 MUST NOT 被判定为完全可复现，差异报告须注明未固定输入条目

### Requirement: 模块内部设计自由度与上层契约变更规则
本模块的内部类、函数、目录结构、解析与缓存策略、配置语言、错误码细分和测试组织
SHALL 由 `member` 自行决定，只要外部可观察行为满足本 spec。若实现需要改变公共
身份、时间/单位语义、引用完整性规则、动作生命周期或适配边界，`member` MUST 暂停
实现并提出上层 spec 修订，经 `lead` 与 Reviewer 批准后再继续。

来源追踪：`REQ-EV-012`；上层 Requirement「成员模块级 Spec 追踪上层契约」。

#### Scenario: 内部实现调整
- **WHEN** member 重构模块内部解析流程、缓存或错误码粒度，而外部判定结论、输入视图语义和错误类别不变
- **THEN** 该调整不需要修改本 spec 或上层 spec

#### Scenario: 实现需要改变公共语义
- **WHEN** member 发现必须改变公共 ID 语义、时间偏差规则或跨域引用要求才能实现
- **THEN** 实现暂停并提出上层 spec 修订，MUST NOT 在模块 PR 中静默改变公共契约
