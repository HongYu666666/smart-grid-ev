## Why

正式进度安排在 2026.08 进入新系统代码开发，8.1—8.7 要求形成总体架构、模块拆分和单场景数据流，8.8—8.14 要求搭建可运行框架的场景加载能力。已接受的
`unified-ev-grid-data-model` 只固定了跨模块公共语义：身份、运行归属、时间、单位、
版本、来源、质量、引用完整性、结果/错误和证据边界，明确把字段、校验、转换、
错误细分和测试留给成员模块级 change。

当前仓库缺少这一层：`docs/deliverables/电动汽车场景基础数据清单.md` 记录了七类
数据的对象 ID、单位、粒度、来源、证据和缺口，但它是来源/缺口账本，不是运行时
可校验的输入契约。因此场景加载入口无法判断一批输入是否可用、缺失数据如何拒绝、
受限数据如何登记、同一次运行的输入如何形成可复现证据。

归档 change `2026-07-31-define-unified-ev-grid-data-model` 的 tasks 4.1／4.2 已把
该工作转交 Issue #19，要求 `member` 在 8.1 后从最新主分支创建独立的数据准备/
场景输入模块 change。本 change 即为该移交任务的落地。

## What Changes

- 定义数据准备/场景输入模块的外部契约：场景输入包的组成、必备元数据、
  逐类数据的字段级要求，以及模块向下游发布的输入视图。
- 定义启动前校验顺序与判定：Schema 与版本、来源与完整性、对象身份唯一性、
  单位与符号、时间与采样、跨域引用、数据质量与缺口。
- 定义结构化输入错误分类，使调用方可区分“修正输入”“补充来源”“受限继续”
  和“拒绝启动”。
- 定义仓库外受限数据的登记方式：只登记标识、版本、哈希、位置类别和共享边界，
  不把数据文件、密钥或个人绝对路径纳入仓库。
- 定义输入侧运行证据：输入清单、哈希、数据集版本、转换记录和随机种子引用，
  支持同版本回放与差异报告。
- 定义模块内部可自由设计的范围，以及必须先修订上层 spec 才能改变的公共语义。
- 形成一份 member 侧成果文档 `docs/deliverables/场景输入数据准备模块设计说明书.md`。

### Non-goals

- 不实现运行时代码、CLI、数据库、序列化格式、网页或可视化。
- 不实现或选择 pandapower 适配器，也不确定最终生产内核。
- 不定义配网潮流、车辆演化、交通、充电排队等领域内部状态机与算法。
- 不定义动作校验、潮流约束校验和不少于 8 类安全校验的最终分类。
- 不修改已归档 change、已接受 spec 或 `REQ-EV-*` 的编号与业务含义。
- 不修改 `docs/deliverables/典型场景-业务需求-孪智功能映射表.md`。
- 不把 v1、V2Sim 或 pandapower 的样例字段固定为新系统正式输入格式。
- 不宣称任何 `REQ-EV-*` 已实现；本 change 只交付模块契约。

## Capabilities

### New Capabilities

- `ev-scenario-input-data-preparation`: 定义电动汽车承载力提升单场景的输入包
  组成、字段级契约、启动前校验、结构化输入错误、受限数据登记和输入侧运行
  证据要求，作为下游场景加载、孪生初始化和回放的唯一输入来源。

### Modified Capabilities

无。本 change 引用已接受的 `unified-ev-grid-data-model` 作为上层合同，
不修改其 Requirement、Scenario 或语义。
