## 1. 目标、依据与边界

### 1.1 设计目标

统一数据模型用于连接场景数据、配电网、车辆/交通、充电设施、孪智交互、
安全校验、结果评估和运行证据，使一次仿真中的输入、事实、提案、裁决、执行、
结果与指标可以按对象和时间追踪。

设计遵循以下原则：

- 公共合同独立于 pandapower、OpenDSS、V2Sim 和 v1 的私有对象；
- 定义对象、时序值、事实快照、事件和动作提案相互区分；
- 智能体只能提出动作，孪生/安全校验层负责接受、拒绝和原子提交；
- 正式数据缺失时记录缺口，不用参考样例静默替代；
- 运行结果必须具有版本、输入、环境和证据链。

- 不定义数据库表、Python 类、API 路由或文件格式；

- 不以本文证明新系统已通过连续 `24×7` 小时、95% 覆盖率或 8 类安全校验。

## 2. 总体模型

统一数据模型分为三层：

```text
场景与运行上下文
        │
公共语义内核
ID｜时间｜单位｜版本｜来源｜质量｜状态｜事件｜动作｜结果｜错误｜证据
        │
 ┌──────┼─────────┬──────────┬────────────┐
配电网领域   EV/交通领域   充电设施领域   孪智交互/安全校验
        │           │           │
配网后端适配器   EV/交通适配器   其他数据/模型适配器
```

- **公共语义内核**只定义跨模块必须一致的含义。
- **领域模块**维护本领域事实、规则和内部状态。
- **后端适配器**完成公共合同与候选工具之间的显式转换。

上层模块不得读取候选后端的 DataFrame 索引、内部类实例或临时内存地址来识别
公共对象；后端私有结果只可作为带来源的诊断附件。

## 3. 公共语义内核

### 3.1 公共包络

所有跨模块对象、消息、结果和错误至少表达下列语义。具体字段名由模块级
OpenSpec 决定。

| 语义 | 系统级要求 | 拒绝条件 |
| --- | --- | --- |
| 身份 | 稳定、唯一、含类型或命名空间的公共 ID | 重复、悬空、类型冲突或只提供后端行号 |
| 运行归属 | 通过 `run_id` 关联同一次配置、输入、事件、动作和结果 | 缺失或跨运行混用 |
| 时间 | 带时区的绝对时间或明确相对时间、`step_index`、步长 | 隐式本地时间、倒序或超过允许偏差 |
| 单位 | 物理量绑定明确单位和符号约定 | 未知单位或未经记录的隐式换算 |
| Schema | 声明公共 schema 版本 | 不支持的主版本 |
| 生产者 | 声明模块、后端/模型/策略及版本 | 无法确定生成者 |
| 来源 | 声明来源类型、位置/标识、生成方式和可选哈希 | 正式输入来源不明 |
| 质量 | 声明有效、缺失、估算、受限或不可用等质量状态 | 使用不可用数据形成事实快照 |
| 关联 | 通过对象、事件、动作或因果 ID 形成追踪链 | 关联对象不存在或版本不匹配 |

### 3.2 定义对象、时序值、快照和事件

| 类型 | 含义 | 关键约束 |
| --- | --- | --- |
| 定义对象 | 相对稳定的身份、拓扑和设备/车辆/站点参数 | 带版本和有效期；变更不得静默覆盖历史 |
| 时序值 | 某对象在某时刻的观测或计算值 | 带时标、单位、质量和来源 |
| 状态快照 | 某次运行、某一步的一致事实视图 | 只含已确认事实；记录组成数据版本 |
| 事件 | 在明确时间对明确对象发生的离散事实或外部注入 | 可排序、去重、关联和回放 |

回放使用已记录事件和已接受动作推进，不隐式重新调用非确定性智能体。事件
晚到、重复或冲突的裁定规则由事件模块 change 细化，但必须记录处理结果。

## 4. 领域对象族

本文只规定跨模块可见的对象族和最低语义，详细字段留给模块级设计。

| 领域 | 公共对象族 | 跨模块最低语义 | 对应需求 |
| --- | --- | --- | --- |
| 场景/运行 | 场景定义、运行配置、运行实例、统一时钟 | 时间范围、步长、版本、随机种子、输入引用、状态 | `REQ-EV-001`、`009` |
| 配电网 | 节点、支路、变压器、开关、负荷、电源、储能 | 拓扑引用、电气参数、可用状态、相别扩展、时序状态 | `REQ-EV-005`、`008`、`012` |
| 常规负荷 | 负荷定义、负荷曲线、预测或修正值 | 配网节点映射、功率单位、符号、时间与来源 | `REQ-EV-001`、`005` |
| EV/交通 | 车辆、行程、道路节点/边、路径、道路事件 | 身份、位置/拓扑、SOC/能耗、时间、状态和来源 | `REQ-EV-002`、`003` |
| 充电设施 | 站点、充电桩、队列、会话、计量 | 资源身份、能力、占用、功率/能量、车辆和配网映射 | `REQ-EV-004`、`008` |
| 孪智交互 | 状态观察、动作提案、校验、执行反馈 | 提议者、快照版本、目标、有效时间、生命周期和原因 | `REQ-EV-006`、`007` |
| 异常与恢复 | 故障/异常事件、降级、恢复、保底状态 | 影响对象、严重度、触发/恢复条件、补偿证据 | `REQ-EV-010` |
| 结果与评估 | 结果、指标定义、指标值、差异报告 | 运行、输入、窗口、单位、口径、证据和质量 | `REQ-EV-009`、`011` |

## 5. 跨领域引用

跨领域引用必须显式、可配置、可检查并带映射版本，至少覆盖：

- 车辆当前位置、行程端点与交通节点/边；
- 车辆、充电会话与充电站/桩；
- 充电站或 EV 聚合负荷与配电网节点/负荷对象；
- 常规负荷、新能源、储能与配电网对象；
- 状态快照与组成它的对象、时序值和数据版本；
- 动作与提议者、目标对象、依据快照、校验和执行结果；
- 指标值与运行、结果、事件、动作和指标定义。

映射必须表达端点类型、有效时间、版本和来源。出现悬空引用、重复公共 ID、
类型不兼容或无法解析的映射时，系统拒绝启动或拒绝该批输入，并返回冲突对象。

## 6. 时间、单位与一致性

### 6.1 时间

同一状态快照中的配网、车辆、交通和充电数据必须属于同一 `run_id` 和可比较
时刻。系统同时保留：

- 带时区的绝对时间，用于数据来源和外部事件对齐；
- 仿真相对时间与 `step_index`，用于确定性推进；
- 时间步长与数据采样周期，用于重采样和质量判断。

允许偏差、插值、晚到事件窗口和同一步事件优先级由后续模块 change 配置化
定义；任何转换都要保存原始时标、规则和结果，不能猜测。

### 6.2 单位

功率、能量、电压、电流、距离、速度、时间和费用等物理/业务量必须声明单位。
转换发生在模块或后端边界，并保存原始值、原始单位、目标单位和转换规则。
功率正负号、标幺值基准和相别含义必须在相关模块 spec 中显式约定。

## 7. 事件模型

公共事件至少表达事件身份、类型、发生时间、记录时间、来源、影响对象、负载、
运行归属、因果/关联关系和处理状态。

```text
外部输入/领域事实
        │
   事件校验与排序
        │
  状态推进或拒绝/补偿
        │
状态快照 + 处理记录 + 后续关联事件
```

同一步车辆到站、充电开始和配网负荷变化必须按获批规则排序并保留关联链。
重复事件不能静默重复修改状态；晚到事件必须被拒绝、补偿或标记受限。

## 8. 动作与安全裁决

### 8.1 动作生命周期

```text
proposed
   ├─ rejected
   └─ accepted → executing → executed
                         └─ failed → rolled_back / safe_fallback
```

动作至少关联提议者、目标对象、有效时间、参数、策略版本、依据快照、校验记录、
执行结果和当前生命周期。

- 智能体只能创建 `proposed`；
- 孪生/安全校验层决定 `accepted` 或 `rejected`；
- 后端只执行已接受动作；
- `accepted` 不等于事实已改变，只有 `executed` 表示原子提交；
- 失败不得留下跨模块半提交状态，必须记录回退或保底结果。

### 8.2 最低校验边界

公共校验至少容纳 Schema、引用、时间、单位、SOC、资源、功率、潮流、电压、
载流、通信、业务规则和动作冲突等类别。最终不少于 8 类安全校验的分类和
统计口径由后续安全校验 change 固化，本文不提前宣称完成。

## 9. 后端适配器

### 9.1 配网适配器

公共输入至少包含版本化拓扑、设备参数、常规/EV 聚合负荷、已接受动作、
时间上下文和单位；公共输出至少包含收敛状态、母线电压、支路功率/载流、
网损、越限、结构化错误和运行元数据。

适配器不得伪造不收敛时的电压/载流结果，也不得只返回日志字符串。

### 9.2 EV/交通/充电适配器

公共输入输出映射到车辆、行程、道路、站点、会话、事件和时序值。V2Sim 或
其他候选私有对象可作为适配器内部实现和诊断附件，但不能成为调用方依赖。

## 10. 结果、错误、指标与证据

### 10.1 结构化结果和错误

结果关联运行、输入、动作/事件、时间、生产者和版本。错误至少区分：

- 输入、引用、时间或单位校验错误；
- 后端不可用、超时或求解不收敛；
- 动作违规或执行失败；
- 内部异常。

错误还要表达可重试性、当前安全状态和诊断引用，使调用方可以选择修正输入、
重试、回退或停止。

### 10.2 指标

指标定义与指标值分开版本化。定义包含含义、单位、时间窗口、聚合方法、缺失
值处理和基准方案；指标值必须回链到运行和原始结果。输入不完整时标记为
不可计算或受限，不以默认零或参考项目结果替代。

### 10.3 运行证据

可验收运行至少记录 schema、数据集、配置、后端/模型/策略版本、输入哈希、
动作序列、事件、随机种子、环境、起止时间、退出状态和结果引用。v1、V2Sim
或候选后端运行成功单独登记为参考证据，不能升级新系统需求状态。

## 11. Schema 演进

公共合同声明 `schema_version`。不支持的主版本必须拒绝；兼容的小版本规则由
模块级 change 说明。旧版本转换必须显式、可测试、可记录，不允许运行时静默
猜测字段含义。

本阶段不选择具体版本规范、序列化库或迁移框架。

## 12. Lead 与 member 的细化边界

### 12.1 Lead 固定的上层契约

- 公共身份、运行、时间、单位、版本、来源和质量语义；
- 定义对象、时序值、状态快照、事件和动作的区分；
- 动作裁决与原子提交责任；
- 后端私有模型隔离；
- 结果、错误、指标和运行证据的最低追踪边界。

### 12.2 Member 可以自行设计

- 模块内部类、函数、文件和存储结构；
- 领域详细字段、内部状态机、缓存和算法；
- 边界转换实现、错误细分和测试组织；
- 在不改变上层语义前提下的兼容策略。

成员 change 必须声明上层 change、对应 Requirement/Scenario、负责模块、
必须遵守的外部契约、允许自行决定的内部设计、依赖和验收。若需改变公共语义，
先提出上层 spec 修订，经 Review 后再继续。
