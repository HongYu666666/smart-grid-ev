本报告统一比较 OpenDSS、GridLAB-D、pandapower 和 PowerModelsDistribution，并选择一个进入下一阶段验证的 PoC 首选。所有项目都是新系统重新开发时的参考资产；候选项目的安装、运行和源码目录均不计入新系统实现状态，也不构成代码或验收 baseline。

## 1. 范围与结论摘要

### 1.1 本轮结论

- 首选 PoC 后端：pandapower `v3.5.4`。理由是它在当前 Linux/Python 3.13 环境已达到 E3，可直接表达负荷、线路和潮流结果，且 Python API 最适合先验证统一数据模型与适配器契约。
- 工程校核备选：OpenDSS `11.0.0.1`。其不平衡配网、QSTS 和 DER 分析能力适合作为后续交叉校核对象，但官方发行与接口边界需要单独环境验证。
- 优化路线备选：PowerModelsDistribution `v0.16.0`。其多导体不平衡 PF/OPF 与多种数学模型适合后续优化 PoC；Julia/JuMP 和求解器边界不进入首轮 Python 适配。
- GridLAB-D `v5.3.0` 暂缓进入首轮 PoC。它保留为事件驱动、设备/建筑和联合仿真的候选，不因本轮未安装而判定能力不足。
- 本轮没有候选被“淘汰”。只有官方限制或充分实测才能支持淘汰结论。

### 1.2 非目标

- 不确定最终生产内核；
- 不把候选依赖加入新系统正式环境；
- 不实现生产适配器、长时间连续运行或 E4 项目数据验证；
- 不代写 member 负责的 V2Sim 运行结论和代码目录。
