本报告用于统一比较 OpenDSS、GridLAB-D、pandapower 和 PowerModelsDistribution 的项目能力与证据，并引用 member 独立提交的 V2Sim 运行证据说明场景层边界。所有对象均为候选参考项目；任何候选项目安装或案例运行成功，都不代表新系统已经实现，也不自动成为新系统代码或验收基线。

## 1. 评估目标

1. 使用同一字段比较四个配电网后端；
2. 记录 V2Sim 中交通、EV、充电/V2G、配网插件与 Python 编排层的边界；
3. 区分资料确认、安装/导入、最小案例和项目数据验证；
4. 形成“继续 PoC、保留候选、暂缓、淘汰”的阶段建议；
5. 为统一数据模型、仿真内核适配器和后续 PoC change 提供输入。

本阶段不强制选出唯一主仿真内核，也不修改新系统运行时代码或正式依赖。

完成统一比较后，仅为进入 PoC 的首选后端建立 `docs/reference_catalogs/grid_backend/<selected-project>/` 完整函数、类和方法目录；其他候选只保留本报告中的比较和证据。全量目录由工具生成，核心开发链路逐项人工复核，其余模块按模块抽检；本报告不重复粘贴逐符号内容。

## 2. 证据等级

| 等级 | 含义 | 最低证据 |
| --- | --- | --- |
| `E0` | 尚未确认 | 无官方来源或仅有待核线索 |
| `E1` | 官方资料确认 | 官方文档、官方仓库、发布或许可证 |
| `E2` | 本地安装/导入确认 | 隔离环境、版本、命令和成功输出 |
| `E3` | 最小案例运行确认 | 输入、命令、输出、运行时间和结果检查 |
| `E4` | 项目数据/接口验证 | 项目数据映射、接口试验和可复现结果；仍不代表新系统已实现 |

证据等级按“实际完成的最深步骤”记录。安装或运行失败时保留环境、命令、错误摘要和下一步判断，不把当前环境失败扩大为项目能力不足。

## 3. 统一评价维度

| 维度 | 必填内容 | 核查方式 |
| --- | --- | --- |
| 项目身份 | 官方名称、官方 URL、维护组织 | 官方仓库/文档 |
| 评估版本 | 版本、发布日期或提交 SHA、评估日期 | 发布页/仓库提交 |
| 许可证 | 许可证类型、附加限制 | 官方 LICENSE |
| 配网建模范围 | 平衡/不平衡、单相/三相、元件和拓扑能力 | 官方模型说明与案例 |
| 求解能力 | 潮流、最优潮流、时序、故障或其他能力 | 官方文档与最小案例 |
| 时序与控制 | 时间推进、事件、控制动作、批量实验 | API/案例/运行记录 |
| 编程接口 | Python、Julia、CLI、服务或文件接口 | 官方 API 文档与导入 |
| 平台与依赖 | 操作系统、运行时、求解器、外部程序 | 安装文档与实际环境 |
| 输入数据 | 拓扑、参数、负荷、控制和单位要求 | 示例模型与 Schema |
| 输出数据 | 电压、功率、载流、收敛、日志和错误 | 最小案例结果 |
| 可复现性 | 安装、输入、命令、输出位置和检查方法 | E2—E4 记录 |
| 性能与连续运行 | 运行时间、规模、稳定性和批量能力 | 实测；未测则明确标注 |
| EV 场景适配 | 与充电负荷、站点控制、V2G 和事件的接口边界 | 对照 `REQ-EV-005/007/011/012` |
| Python 编排边界 | 适配器需要转换的对象、时标、动作和错误 | 接口草图/PoC |
| 主要风险 | 许可、维护、平台、数据、精度和集成风险 | 官方证据与实测 |
| 阶段建议 | 继续 PoC、保留候选、暂缓或淘汰 | 与证据等级一致 |

## 9. 待 Review 项

- 四个配网后端的官方来源、版本、许可证和维护状态；
- 候选最小案例是否使用同一数据规模和结果检查口径；
- V2Sim 配网插件与未来主仿真内核的责任边界；
- 现有项目数据能否支持 E4，或需先完成统一数据模型；
- 快速 Python 编排与工程高保真校核是否需要分层工具路线。
- 首选 PoC 后端确定后，其代码目录的固定版本、扫描范围和语言解析器。
- 首选后端目录已覆盖全量生产源码符号，所有功能说明非空且复核状态明确；
- 模型加载、网络对象、求解、时序/控制、结果和错误处理核心模块已逐项人工复核。
