## 2. 使用边界

- 新系统必须依据任务书、正式计划和 OpenSpec 独立完成架构、接口、实现与测试，不继承任何参考项目的完成状态。
- 主映射表只写新系统目标责任、目标组件、新系统证据和目标状态；不得使用 v1 类名或参考项目命令充当新系统设计与验收证据。
- 参考资产评估表单独记录 v1、V2Sim 和后续项目的可参考内容。参考状态“已复现”只说明参考代码运行成功。
- 孪生体负责事实状态、确定性演化和约束校验；智能体负责感知、预测、建议和动作提案；查表、回放、潮流计算和确定性校验属于工具/模型组件。
- 新系统目标状态仅使用：`已验证`、`部分具备`、`规划中`、`待裁定`。参考状态仅使用：`已复现`、`部分可参考`、`待调研`、`不适用`。
- 当前尚无新系统运行时代码，因此除需要后续选型的事项外，目标状态均为 `规划中`。只有新系统自身产生可复现证据后才能改为 `部分具备` 或 `已验证`。

## 7. Review 与后续同步要求

1. `member` Review 时分别检查“新系统目标映射”和“参考资产映射”，确认没有把参考类名、命令或结果写成目标系统实现。
2. 完成 OpenSpec `1.2`、`2.1`、`2.2` 时，《软件需求分析报告》必须复用 `REQ-EV-001`—`REQ-EV-012`，并保持新系统状态与参考状态分离。
3. 场景调研报告应继续补充 v1、V2Sim 和后续项目的参考证据、适用边界和数据缺口，不得把“已复现”改写成“新系统已验证”。
4. 后续若决定采用参考代码，必须在对应设计/实现 change 中记录选型理由、许可证、接口适配和新系统测试证据，然后才能更新主映射表的 `evidence` 与 `status`。
5. `lead` 仅可在 Reviewer 意见收敛、需求 ID 同步和 OpenSpec 校验通过后把本表从“待 Review”改为“已验收”。
