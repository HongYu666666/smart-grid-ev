## 说明

本清单逐项记录电动汽车承载力提升场景所需的基础数据对象，为 Issue #12
统一数据模型设计提供输入。各数据表记录对象、单位、时间粒度、对象 ID、来源、
当前证据、缺口和后续模块归属；以下映射表把数据类别分别追踪到稳定需求编号和
上层系统级 Requirement/Scenario。

## 上层 Requirement/Scenario 映射

| 上层 Requirement | 本清单输入 | 对应 Scenario/后续校验 |

| 事件可排序、关联和回放 | 第6节动作与事件及其时间粒度 | 同一步跨领域事件；晚到/重复事件 |
| 动作具有校验和执行生命周期 | 站点选择、充电模式、V2G、功率调节 | 动作接受、拒绝、执行失败和回退 |

| 指标定义和值可追踪 | 第7节指标及来源/缺口 | 需求覆盖率；指标输入不完整 |
| 运行证据可复现 | 数据集标识、版本、哈希/缺口及运行记录 | 同版本回放；参考证据不提高新系统状态 |
| 成员模块级 Spec 追踪上层契约 | 各表“后续模块”列 | 数据准备模块细化；公共契约变更先修订上层 |

## 8. 证据等级说明

| 等级 | 含义 |
|------|------|
| E0 | 未尝试 |
| E1 | 有代码/配置/文件但未在隔离环境执行验证 |
| E2 | 安装/导入成功或文件内容已确认 |
| E3 | 固定输入+命令+输出+结果检查齐备的最小案例运行 |
| E4 | 输出经交叉验证或与基准对比 |

## 9. 适用边界

- 本清单基于 v1 参考项目、V2Sim 1.4.4 和 pandapower 3.5.4 的数据结构整理
- 所有"E1"项目为参考资产，不等于新系统已具备
- 新系统数据模型设计(Issue #12)应从本清单出发，但不受限于参考项目的数据格式
- 后续模块归属为初步建议，以上层 OpenSpec change 为准
