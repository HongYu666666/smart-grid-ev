## 2. 场景业务流程

### 2.1 场景定义

电动汽车承载力提升场景研究的核心问题是：在城市配电网中，大规模 EV 充电负荷接入后如何保证电网安全运行、提升 EV 接纳能力。

### 2.2 业务全流程

```
┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ EV出行   │ →  │ 充电需求  │ →  │ 充电站选择│ →  │ 排队/充电 │ →  │ 负荷接入  │
│ 产生     │    │ 触发      │    │ 决策      │    │ 过程      │    │ 配电网    │
└─────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
      ↑                                                              │
      │              ←──── 动态电价/拥堵反馈 ────←                     │
      └────────────────────────────────────────────────────────────────┘
```

### 2.3 业务对象清单

| 序号 | 业务对象 | 描述 | 关键属性 |
|------|---------|------|---------|
| OBJ-1 | 电动汽车 | EV车辆实体 | 位置、SOC、电池容量(61.4kWh)、行驶状态、人群类别 |
| OBJ-2 | 交通路网 | 城市道路拓扑 | 32节点、106条有向路段、时变交通流、OD矩阵 |
| OBJ-3 | 充电站 | EV充电设施 | 7座站点、快充桩(120kW)、慢充桩(7kW)、排队队列 |
| OBJ-4 | 配电网 | 电力分配网络 | 24节点、线路阻抗、基础负荷、分布式资源 |
| OBJ-5 | 动态电价 | 基于电压偏移的定价 | 分时电价+实时调整、1h/5min分辨率 |
| OBJ-6 | 交通流 | 路段车辆流量 | 5min分辨率、32×32流量矩阵 |

### 2.4 控制动作

| 动作 | 执行者 | 约束条件 |
|------|--------|---------|
| 充电站选择 | 智能体/用户 | SOC可达性、排队长度、电价 |
| 充电模式选择 | 智能体 | 快充/慢充、目标SOC、可用时间 |
| 动态电价调整 | 配电网侧 | 电压偏移约束、公平性 |
| V2G放电 | 智能体 | SOC下限、用户意愿、电网需求 |
| 充电功率调节 | 充电站 | 变压器容量、电压安全 |

### 2.5 物理与业务约束

| 约束类型 | 具体约束 | 来源 |
|---------|---------|------|
| 电池物理 | 0 ≤ SOC ≤ 1，充电功率曲线 P(SOC) | 电池特性 |
| 电网安全 | 节点电压 0.95~1.05 p.u.，线路不过载 | 配电网运行规程 |
| 充电站容量 | 快充桩数 ≤ 上限，慢充桩数 ≤ 上限 | 物理设备 |
| 交通约束 | 行驶能耗与路况相关，时变最短路 | 交通流模型 |
| 用户行为 | 出行OD分布、充电时间偏好 | 统计规律 |

### 2.6 评价指标

| 指标 | 含义 | 计算方式 |
|------|------|---------|
| EV承载力 | 配电网可接纳的最大EV数量 | 逐步增加EV至电压越限 |
| 负荷峰谷比 | 充电负荷的峰谷差异 | (P_max - P_min) / P_avg |
| 电压偏移 | 节点电压偏离额定值 | max(|V_i - 1.0|) |
| 用户等待时间 | 充电排队等待时长 | 平均等待时间(min) |
| 充电成本 | 用户单次充电费用 | 电价×电量+时间成本 |
| 负荷预测精度 | 预测与实际负荷偏差 | MAE, RMSE, R² |

### 2.7 异常情形

| 异常 | 影响 | 处置 |
|------|------|------|
| 充电站故障 | 车辆无法充电，负荷转移 | 引导至邻近站点 |
| 电压越限 | 配电网不安全运行 | 拒绝新增充电负荷/削减功率 |
| 极端天气 | 充电效率下降、出行模式变化 | 温度-效率修正 |
| 交通拥堵 | 行驶能耗增大，到达延迟 | 路径重规划 |

## 5. V2Sim 典型案例运行记录

### 5.1 运行环境

- 操作系统：Windows 10/11
- Python：3.12.7 (Anaconda base)
- V2Sim版本：1.4.4 (pip install v2sim)
- 交通引擎：UXsim（内置，无需额外安装）
- 配电网引擎：FPowerKit 0.4.3（自动依赖安装）

### 5.2 运行案例

- 案例名称：ux_12nodes
- 案例路径：`v2sim-main/v2sim-main/cases/ux_12nodes/`
- 配电网：12节点
- 交通引擎：UXsim
- 车辆数：1000（500 EV + 500 GV）
- 仿真步数：17280步（172800秒 = 2天）
- 运行时间：约9秒

### 5.3 运行命令

```bash
# 1. 安装
pip install v2sim

# 2. 生成车辆行程数据
v2sim-gen-trip -d "<案例路径>" -n-ev 500 -n-gv 500

# 3. 启动GUI运行仿真
v2sim-gui
# → 添加项目 → 选择ux_12nodes文件夹 → 开始仿真

# 4. 查看结果
v2sim-viewer -d "<案例路径>/results"
```

### 5.4 输出结果

- `results/fcs.csv`：快充站负荷时序数据
- `results/scs.csv`：慢充站负荷时序数据
- `results/bus.csv`：母线电压/功率数据
- `results/line.csv`：线路潮流数据
- `results/utn.csv`：交通网络数据
- 可视化：快充站总负荷曲线（峰值约580kW，早高峰8:00-12:00）

### 5.5 可复用能力边界

| V2Sim可复用 | 不可直接复用（需Python编排层） |
|------------|---------------------------|
| EV出行生成(OD驱动) | 自定义智能体决策逻辑 |
| 交通流仿真(UXsim/SUMO) | T型架构孪生体编排 |
| 充电排队与功率仿真 | LLM顾问接入 |
| V2G放电模拟 | 自定义评价指标 |
| 配电网潮流(FPowerKit) | 拓扑画布可视化 |
| 结果导出(CSV) | 多场景对比分析 |

## 7. 结论与后续建议

### 7.1 核心结论

1. **已有资产丰富**：ev_charging_v1 中的仿真代码经过一致性校验（4场景零误差），smart_grid_core 的T型架构已可运行
2. **V2Sim 验证通过**：可作为交通+充电仿真的基础能力，但配电网计算（FPowerKit）精度需进一步评估
3. **智能体实现为主要缺口**：架构已就绪但AI模型（DRL/Informer/ST-GCN/BNN）均为规划状态
4. **配电网主内核待选型**：是继续用线性规划/FPowerKit 还是切换到 pandapower/OpenDSS 需要下一阶段验证

### 7.2 后续工作建议

- 进入 `assess-grid-simulation-backends` change，验证候选配电网仿真工具
- 明确交通仿真路线（自研模型 vs V2Sim 接管）
- 启动 AG-1（出行决策智能体）的 Gym 环境搭建
- 建立统一数据模型，对接 V2Sim 输出与 smart_grid_core 输入
