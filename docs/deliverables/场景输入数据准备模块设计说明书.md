## 1. 模块定位与边界

### 1.1 定位

本模块是单场景仿真链路的唯一输入入口，职责是把一批异构数据变成可判定、可追踪、
可回放的公共输入视图，并在启动前拒绝不合格输入。

```text
数据集条目（仓库内 / 仓库外受限 / 固定参数生成）
        │
数据准备与场景输入模块
  清单校验 → 来源校验 → 身份校验 → 度量校验 → 引用校验 → 质量判定
        │
公共输入视图 + 受限说明 + 输入侧证据
        │
场景与实验管理 → 各领域孪生初始化 → 统一时钟步骤 0 快照
```

### 1.2 负责范围

- 场景输入包的清单、运行上下文与必备条目集合校验；
- 数据集条目的来源、位置类别、完整性证据、质量状态与共享边界登记；
- 公共对象身份唯一性与命名空间校验；
- 单位、符号、时区、采样粒度和标幺基准的入口统一与转换留痕；
- 车辆、道路、站点、桩、聚合负荷与配网对象之间的跨域引用解析；
- 缺口判定：阻塞启动或受限可用；
- 结构化输入错误；
- 输入侧运行证据。

### 1.3 不负责范围

- 配网潮流、车辆演化、交通推演、充电排队等领域状态推进；
- 动作提案、动作校验、安全裁决与不少于 8 类安全校验分类；
- 配网后端适配器实现与最终生产内核选择；
- 指标计算、结果存储、网页展示与可视化；
- 受限数据的分发、脱敏与权限审批。

## 2. 输入包结构

模块的外部输入单位是带清单的场景输入包，不接受清单外路径的隐式补齐。

| 语义槽位 | 最低要求 | 缺失后果 |
| --- | --- | --- |
| 包身份 | 稳定包标识与版本 | 拒绝启动 |
| 目标场景 | 场景标识与版本 | 拒绝启动 |
| 公共 schema | schema 版本声明 | 主版本不支持则拒绝 |
| 时间上下文 | 带时区起止时间、步长、步索引起点 | 拒绝启动 |
| 数据集清单 | 各语义类别的条目标识与版本 | 清单不完整错误 |
| 跨域映射 | 映射条目、端点类型、映射版本 | 引用不可解析错误 |
| 随机性 | 随机种子或其引用 | 无法声明可复现 |
| 必备集合 | 本次运行的必备条目列表 | 无法判定缺口后果 |

## 3. 数据集条目契约

每个条目独立于内容登记，避免“文件存在”被当成“数据可用”。

| 语义槽位 | 取值范围 |
| --- | --- |
| 标识与版本 | 稳定数据集标识 + 版本 |
| 语义类别 | 配网拓扑、常规负荷、车辆/行程、交通、充电设施、动作/事件模板、约束/指标定义 |
| 来源类型 | 项目正式数据、参考项目资产、公开标准算例、固定参数生成 |
| 位置类别 | 仓库内、仓库外受限、生成自固定参数 |
| 完整性证据 | 哈希，或明确的“无完整性证据” |
| 质量状态 | 有效、估算、受限、缺失、不可用 |
| 共享边界 | 可入库、仅项目组内、禁止分发 |

条目位置不得使用个人绝对路径。仓库外受限条目只登记标识、版本、哈希、位置类别和
共享边界。

### 3.1 与基础数据清单的对应

[`电动汽车场景基础数据清单.md`](电动汽车场景基础数据清单.md) 是来源与缺口账本，
本模块把其中每一行转成可判定的条目要求。两类现存事实的处理方式如下：

| 清单条目 | 本模块登记方式 | 判定后果 |
| --- | --- | --- |
| `regional-data-package-20260729` | 仓库外受限 + 已登记 SHA-256 | 可完成来源与完整性校验；不入库 |
| `jun30-parity-baseline` | 仓库外受限 + 无完整性证据 | 标记不可独立校验；若被声明为必备则拒绝启动 |

## 4. 校验分层

校验按固定顺序执行，前一层存在阻塞问题时不进入后一层，避免次生错误淹没根因。

| 层 | 名称 | 主要检查 |
| --- | --- | --- |
| L1 | 包级 | schema 主版本、清单完整性、时间范围与步长、种子引用 |
| L2 | 来源级 | 数据集标识、版本、来源类型、位置类别、完整性证据 |
| L3 | 身份级 | 公共 ID 存在性、唯一性、类型/命名空间 |
| L4 | 度量级 | 单位、符号约定、数值域、时标与采样周期 |
| L5 | 引用级 | 车辆—道路、车辆/会话—站点、站点/聚合负荷—配网、负荷—配网 |
| L6 | 质量级 | 缺失、估算、受限、不可用状态与本次可用性判定 |

判定结论只有三种：可用、受限可用、拒绝。同一输入包重复校验须得到相同结论和相同
问题集合。

## 5. 缺口判定

模块不自行判断业务可接受性，按输入包声明的必备条目集合判定：

| 情况 | 判定 | 附加要求 |
| --- | --- | --- |
| 必备条目缺失/不可解析/质量不可用 | 拒绝启动 | 不进入任何孪生初始化 |
| 非必备条目缺失或质量为估算/受限 | 受限可用 | 标记受限条目、原因和受影响需求/指标 |
| 全部必备条目有效 | 可用 | 记录条目版本与完整性证据 |

不得用默认值、零值或参考项目样例静默填补缺口。受限输入不得支撑“可复现”或“指标
达标”结论。

## 6. 单位、时间与转换留痕

- 物理与业务量必须绑定单位和符号约定；
- 时间必须为带时区绝对时间或明确相对时间与步索引；
- 单位换算、时区归一、重采样、标幺基准换算只在本模块入口执行；
- 每次转换记录原始值/原始单位或时标、目标形式、规则标识；
- 缺单位、缺时区、含义不明的字段直接返回度量非法错误，不猜测。

下游模块不再做二次换算，避免同一物理量被多次隐式转换。

## 7. 结构化输入错误

| 类别 | 触发条件 | 调用方期望动作 |
| --- | --- | --- |
| schema 不兼容 | 公共 schema 主版本不支持 | 更换兼容输入，不降级解析 |
| 清单不完整 | 必备条目缺失或清单自相矛盾 | 补齐条目 |
| 来源不可确定 | 缺来源类型、版本、位置类别或使用个人路径 | 补充来源登记 |
| 完整性缺失 | 必备条目缺哈希等完整性证据 | 补充证据或改判受限 |
| 身份冲突 | 公共 ID 重复、缺失、类型不符或仅为后端行号 | 修正标识 |
| 度量非法 | 单位未知、符号不明、数值越域、时标不可解析 | 修正字段 |
| 引用不可解析 | 悬空引用、端点类型不兼容、缺映射版本 | 修正映射或对象集合 |
| 质量不可用 | 必备条目质量为缺失/不可用 | 取得数据或调整必备集合 |
| 内部错误 | 模块自身异常 | 重试或上报缺陷 |

每条错误表达类别、可定位对象/条目、期望与实际、是否可重试、当前是否允许启动。
不允许只返回日志字符串或布尔失败标记。

## 8. 输入侧运行证据

每次判定产出输入侧证据记录，至少包含：

- 包标识与版本、目标场景与版本、公共 schema 版本；
- 数据集条目及其版本、完整性证据、质量状态、位置类别；
- 转换记录摘要与规则标识；
- 跨域映射版本；
- 随机种子或其引用；
- 判定结论与受限说明；
- 生成时间。

缺版本或完整性证据的条目标记为不可独立校验；含此类条目的运行不得判定为完全可
复现，差异报告须注明未固定输入。
