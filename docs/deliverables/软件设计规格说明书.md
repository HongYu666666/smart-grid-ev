## 2. 总体架构

```text
用户/实验配置
      │
场景与实验管理 ─────── 数据接入与统一对象注册
      │                         │
统一时钟与事件调度 ─────── 统一状态/事件存储
      │                         │
 ┌────┴──────┬────────┬────────┴──────┐
配电网孪生   EV/交通孪生   充电设施孪生   其他领域孪生
 └────┬──────┴────────┴────────┬──────┘
      │       状态快照          │
      └──── 孪智交互网关 ← 智能体/策略
                  │ 动作提案
             安全校验与裁决
             ├─ 拒绝/反馈
             └─ 接受 → 原子执行/回退
                         │
                  结果、指标与证据
```

总体架构采用“配电网主仿真内核 + Python 编排/接口层 + 场景适配器”。首个
配网 PoC 可使用 pandapower，V2Sim 可提供 EV/交通/充电参考能力，但上层模块
只依赖统一合同。

## 3. 模块职责

| 模块 | 主要责任 | 禁止越界 | 对应需求 |
| --- | --- | --- | --- |
| 场景与实验管理 | 加载版本化场景、配置、输入、种子和运行元数据 | 不用未登记参考数据补齐正式输入 | `REQ-EV-001`、`009` |
| 数据接入与对象注册 | 校验 Schema、来源、ID、单位、时间和跨域引用 | 不把后端行号作为公共 ID | `REQ-EV-001`、`008` |
| 统一时钟与事件调度 | 推进步骤、排序/去重事件、形成可回放顺序 | 不隐式重做智能体提案 | `REQ-EV-002`、`009`、`010` |
| 配电网孪生 | 维护网侧事实、调用后端、返回潮流和约束结果 | 不接受未校验动作，不伪造不收敛结果 | `REQ-EV-005`、`012` |
| EV/交通孪生 | 维护车辆、行程、道路、SOC 和交通事实 | 不替智能体决定目标或路线 | `REQ-EV-002`、`003` |
| 充电设施孪生 | 维护站点、桩、队列、会话和计量事实 | 不自行绕过资源/网侧约束 | `REQ-EV-004` |
| 智能体/策略 | 基于快照产生结构化动作提案与解释 | 不直接修改事实状态 | `REQ-EV-006` |
| 孪智交互网关 | 发布快照、接收提案、关联提议者与策略版本 | 不把提案当成已执行事实 | `REQ-EV-006`、`007` |
| 安全校验与裁决 | 校验动作并接受/拒绝，组织原子执行、回退和保底 | 不允许跨模块半提交 | `REQ-EV-007`、`010` |
| 结果、指标与证据 | 记录结果/错误、计算指标、归档可复现证据 | 不用参考项目结果替代新系统结果 | `REQ-EV-009`、`011` |

## 4. 统一数据模型

统一模型的详细系统级定义见
[`统一数据模型设计说明书.md`](统一数据模型设计说明书.md)，本章给出架构使用方式。

### 4.1 公共语义

所有跨模块数据必须表达稳定身份、`run_id`、明确时标与步长、单位、Schema 和
生产者版本、来源、质量及关联。候选后端私有对象在适配器边界转换，不进入
公共调用接口。

### 4.2 数据类型

- **定义对象**：场景、拓扑、设备、车辆、道路和站点等相对稳定定义；
- **时序值**：带对象、时标、单位、质量和来源的观测/计算值；
- **状态快照**：同一运行和步骤下的一致事实视图；
- **事件**：可排序、关联、去重和回放的离散事实；
- **动作**：具有提议、校验、执行和回退生命周期的候选控制；
- **结果/错误**：与运行、输入、动作/事件、时间和生产者关联的结构化输出；
- **指标/证据**：版本化口径、指标值和可复现实验记录。

### 4.3 数据清单与运行时 Schema 的关系

[`电动汽车场景基础数据清单.md`](电动汽车场景基础数据清单.md) 是数据来源、
单位、粒度、证据、质量、共享边界和缺口账本，不是运行时 Schema。清单已经
完成需求及上层 Requirement/Scenario 映射；后续 member 在独立模块 change
中设计字段、校验和转换，lead 负责确认其不改变公共语义。

当前区域数据 ZIP 只作为受限参考资产登记了固定哈希；`jun30` parity 基线文件
未进入 lead 工作区且无哈希。运行时场景加载必须显式拒绝没有可定位来源、版本
或完整性证据的正式输入，不能从本地样例路径静默兜底。

## 5. 关键交互

### 5.1 场景初始化

1. 场景管理加载版本化配置、数据引用和运行参数。
2. 数据接入校验来源、Schema、单位、时间和公共 ID。
3. 对象注册检查拓扑及跨域引用，不完整或冲突时拒绝启动。
4. 各领域孪生建立初始事实，统一时钟形成步骤 0 快照。
5. 实验管理保存输入哈希、环境、后端/模型版本和启动结果。

对应 `REQ-EV-001`、`008`、`009`。

### 5.2 每步联合推进

1. 事件调度器按批准规则处理本步外部事件和领域事实。
2. 各领域孪生推进确定性状态，配网后端计算公共结果。
3. 编排层组合一致状态快照，超时或单位不一致的数据被拒绝或标记不可用。
4. 智能体读取快照并产生 `proposed` 动作。
5. 安全校验层检查 Schema、时序、引用、资源、SOC、功率和网侧约束。
6. 动作被拒绝则事实状态不变；被接受后进入原子执行。
7. 执行成功后提交新状态；失败则回退或进入安全保底状态。
8. 结果、错误、事件、动作和指标写入同一运行证据链。

对应 `REQ-EV-002`—`007`、`010`、`011`。

### 5.3 回放与方案比较

回放读取版本化输入、配置、事件、已接受动作和随机种子，不重新调用非确定性
智能体。结果模块生成可比较输出和差异报告，差异超过批准阈值时不判为可复现。
参考项目回放与新系统回放分开登记。

对应 `REQ-EV-009`、`011`。

## 6. 动作、安全与一致性设计

### 6.1 责任分离

```text
智能体：读取事实 → 产生 proposed
孪生/安全层：校验 → accepted 或 rejected
领域/后端：只执行 accepted
事务边界：executed 或 failed → rolled_back / safe_fallback
```

任何模块不得把 `accepted` 当作已提交事实。跨模块动作需要统一事务或可证明的
补偿/快照回退方案，具体实现在孪智交互模块 change 中细化。

### 6.2 异常处理

结构化错误至少覆盖输入、引用、时间、单位、后端不可用、不收敛、动作违规、
超时、执行失败和内部异常，并表达可重试性及安全状态。异常处理至少可以：

- 拒绝输入或动作且保持上一稳定状态；
- 对可重试故障执行有限重试；
- 对执行失败执行回退/补偿；
- 对高风险或智能体不可用转入保底控制；
- 保存触发、裁决、执行和恢复证据。

### 6.3 数据一致性

- 同一快照的数据必须属于同一运行和可比较时刻；
- 单位转换必须显式并留记录；
- 公共引用端点必须存在且类型兼容；
- 不支持的 Schema 主版本必须拒绝；
- 状态、事件、动作和结果的版本/因果关系必须可回链。

## 7. 适配器边界

### 7.1 配网后端

配网适配器接收统一拓扑、设备参数、常规/EV 聚合负荷、已接受动作、时间和单位，
返回收敛状态、电压、支路功率/载流、网损、越限、结构化错误和运行元数据。
#13 的 PoC 必须可删除，不得让上层依赖 pandapower DataFrame。

### 7.2 EV/交通/充电后端

EV、交通和充电适配器把候选工具数据映射为公共车辆、行程、道路、站点、会话、
事件和时序值。V2Sim 的内部对象、案例规模和结果只作为参考与诊断附件。

## 8. 结果、指标与证据

结果层同时保存：

- 公共结构化结果和错误；
- 输入、配置、事件、动作、状态和生产者版本关联；
- 指标定义与指标值；
- 环境、后端/模型/策略版本、随机种子、输入哈希和退出状态；
- 需要时保存后端原始诊断附件，但不让验收依赖私有格式。

指标输入不完整时标记为不可计算或受限。最终任务书约束必须由新系统自身运行
证据验证，设计文档和参考项目运行不能充当完成证明。

## 9. 模块级 OpenSpec 规则

lead 维护系统级模块、交互和公共合同；member 在上层 change 获批后从最新主
分支创建独立模块 change。每个模块 change 必须说明：

- 上层 change 和对应 Requirement/Scenario；
- 负责模块和不负责范围；
- 必须遵守的外部输入、输出、状态和错误；
- 可自行决定的内部类、字段、算法、存储和测试；
- 依赖、迁移、失败路径和验收方法。

若成员实现需要改变公共对象语义、动作生命周期或适配边界，应暂停实现并提出
上层修订，不在模块 PR 中顺带修改。
