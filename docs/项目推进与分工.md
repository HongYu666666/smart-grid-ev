## 4. 推进节奏

- 窗口开始：lead 说明目标成果、非目标和最低证据，不规定每天必须完成什么。
- 窗口中段：三人进行一次短检查，决定继续、缩小范围或补充资源。
- 日常：组员自主安排；出现影响别人、需要接口裁定或连续一天无法推进的阻塞时，在 Issue 留言。
- 窗口结束：交叉 Review，lead 按 OpenSpec 和证据验收；未完成部分进入下一窗口，不用虚构完成百分比。
- 双周：使用 `docs/软件组双周推进模板.md` 汇总正式成果。

推荐看板状态：`Backlog → Ready → In Progress → In Review → Acceptance → Done`，阻塞任务单独标为 `Blocked`。

## 5. 验收边界

实现者可以声明“已提交、待验收”，Reviewer 可以声明“Review 通过”，只有 lead 可以声明“已验收”。正式进度表中的完成进度只依据已验收成果更新，不依据口头百分比或 Codex 自检结论更新。
