# 车-路-站-网世界模型原型设计书

> 文档状态：研究原型设计输入。当前已实现能力必须以可复现命令或测试记录确认，规划能力不得直接作为验收完成项。

## 1. 原型目标

原型以现有 32 节点交通网、24 节点配网和 7 座充电站映射为第一套世界。即使没有智能体接入，它也能按固定时间步持续生成车辆出行、交通、充电和配网状态，并支持暂停、倍速、事件注入和回放。

## 2. 模块职责

| 模块 | 当前实现 | 后续替换 |
|---|---|---|
| 世界时钟 | Python 后台线程，默认 5 分钟仿真步 | HELICS 时间协调 |
| 场景生成器 | 日内曲线 + 固定种子扰动 | 原始历史曲线、天气与活动数据 |
| 交通求解 | 32 节点聚合流量模型 | SUMO + TraCI |
| 车辆行为 | 私家车/出租车、目的地、SOC 与充电触发 | 原 Markov/OD 数据与行为校准 |
| 站点模型 | 7 站、队列、桩位、快慢充 | 更精细离散事件模型 |
| 配网求解 | 负荷-电压筛查模型 | pandapower 时序潮流 |
| 策略控制 | 内置成本排序基线 | 可插拔智能体或优化器 |
| 记录与回放 | SQLite 快照和事件表 | 时序数据库与对象存储 |
| 沙盘 | 标准 Web API 和浏览器界面 | 可继续复用 |

## 3. 运行顺序

每个时间步依次执行：

1. 推进仿真时钟；
2. 解除到期事件并汇总当前扰动；
3. 生成交通、负荷和新能源外部条件；
4. 计算配网预状态；
5. 推进充电过程和站点队列；
6. 生成车辆行程并更新 SOC；
7. 对充电需求调用基线策略并执行物理校验；
8. 重新计算配网状态和动态电价；
9. 保存状态快照和事件。

重算配网是为了让本时间步新增的充电负荷立即反映到电压和价格中。

## 4. 标准交换对象

所有对象必须包含 `sim_time`、`scenario_id`、`entity_id`、`source` 和 `version`。

- `StateSnapshot`：世界运行状态、聚合指标、交通、配网、站点、车辆和活动事件。
- `WorldEvent`：事件类型、严重级别和结构化载荷。
- `ActionProposal`：控制器提交的动作类型、参数和控制器标识。
- `ValidationResult`：动作是否接受、拒绝原因和原提案。

智能体只能提交 `ActionProposal`。它不能直接写车辆 SOC、队列、道路流量或节点电压。

## 5. API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/state` | 当前状态 |
| GET | `/api/topology` | 交通、配网和站点映射 |
| GET | `/api/history?limit=144` | 最近状态序列 |
| GET | `/api/replay?sim_time=3600` | 指定时间最近快照 |
| GET | `/api/events?limit=100` | 事件记录 |
| POST | `/api/control` | 启动、暂停、单步、重置、倍速 |
| POST | `/api/events` | 注入场景事件 |

## 6. 数据表

`snapshots` 以 `(scenario_id, sim_time)` 为主键保存完整状态 JSON。`events` 保存事件时间、类型、严重级别和完整载荷。固定种子、时间步和车辆数保存在快照指标中。

正式版本建议增加：

- 高频测点时序表；
- 动作提案与校验结果表；
- 场景定义与数据版本表；
- 模块心跳和故障表。

## 7. 故障与回退

- 充电站故障期间不接受新车辆；恢复后基线策略重新将需求分配到在线站点。
- 电压低于紧急阈值时，新的充电动作被物理校验器拒绝。
- 外部智能体超时、断线或输出非法动作时，当前时间步使用基线策略。
- 专业求解器失败时，正式版本应冻结最后可信状态、记录模块故障并进入降级模式，而不是静默生成数据。

## 8. 验收标准

- 连续 7 天共 2016 个 5 分钟时间步可完成；
- 同一随机种子、车辆数和事件表产生相同最终状态；
- 重置后轨迹从零开始；
- 事件在生效期内改变对应状态，到期后自动解除；
- 任意已保存时间点可回放；
- SOC 保持在 `[0, 1]`，站点占用不超过桩位；
- 配网紧急阈值不能被控制器绕过；
- 无智能体时环境仍持续运行。
